# Venue database: floor sheets load from data, not code

## Goal
A venue is saved once, with its floors, rooms and facts. Any event held there picks those floors up automatically. London's QEII Centre becomes the first venue record rather than a special case.

## What the user gets
- **Venues page** (Events → Venues library): a list of saved venues, each showing its name, city, address, floor count and source quality (drawn vector or picture scan).
- **Venue page**: floors in order, with tab marker and title. You can load a venue's SVG floor sheet, reorder floors, rename rooms, and hide venue clutter (lifts, voids, pillar dots) per venue. The London rules move into the data for each venue.
- **Event → venue link**: when you start an event, you pick an existing venue or add a new one. The event's Maps tab then shows that venue's floors. Room colours, uses and logos stay per event, so two events at the same venue don't overwrite each other.
- **London**: the QEII Centre's seven floors are copied into the database exactly as they are drawn today. The London maps then read from the database, but keep the built-in copy as a safety net. If the database can't be reached, or a floor is missing there, the map still draws from the built-in copy and says so.

## What stays the same
- Every London look, gradient, colour default, logo rule, room cut, spill check and export (SVG, Illustrator, PowerPoint, Word, PDF, ZIP) renders the same as today. Tests compare the database copy with the built-in copy shape for shape.
- Nothing about a venue is guessed. Picture scans are still refused or labelled as lower quality, and web research findings still need Confirm before they become venue facts.
- San Francisco stays on hold. It can get a venue record (the InterContinental) with no floors until the hotel's sheets arrive.

## Technical details
- **New tables** (each with GRANTs, RLS, signed-in read and `can_edit_venue` write):
  - `venues`: slug unique, name, city, country, address, timezone, logo_path, source_note.
  - `venue_floors`: venue_id, floor_key, marker, title, position, source_kind (vector/scan), source_name, w, h, shapes jsonb, labels jsonb, off_plan_labels text[], wall_closures jsonb, splits jsonb.
  - `event_venues`: event_id to venue_id (one venue per event for now).
- **Change to `event_map_floors`**: add a nullable `venue_floor_id`, so per-event overrides (room_uses, room_colours) sit on top of a venue floor. Existing rows keep working.
- **Seed**: the QEII seed is a migration with literal INSERTs, generated by a script from `QEII_FLOOR_VECTORS` (plus the off-plan labels, wall closures and reviewer splits). A test asserts the seed matches the built-in data.
- **Server functions**: `src/lib/venues.functions.ts` gets listVenues, getVenue, saveVenue, saveVenueFloor, linkEventVenue and getEventFloors. getEventFloors merges the venue floors with the event's overrides.
- **Code changes**:
  - A loader in `next-london-qeii-vectors.ts` reads from the database and falls back to the built-in array, flagged `source: "bundled"`. It is used by the 3 current consumers.
  - `events.next_.maps.$eventId.tsx` reads via getEventFloors.
  - The start-event form gets a venue picker.
- **Routes**: `/events/venues` (library) and `/events/venues/$slug` (venue page), each with its own head().
- **Order of work**: tables and seed, then functions, then the event maps page, then the London loader with fallback, then the venues pages, then tests, `bunx tsgo --noEmit` and `bunx vitest run`.
